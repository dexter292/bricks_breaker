# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** React Native / Expo + Skia immediate-mode game UI — **not** a web component-library app. No shadcn, Tailwind, or CSS framework. Design tokens apply to Skia fills and thin React Native overlay chrome.

| Property | Value |
|----------|-------|
| Tool | none |

| Component library | none — Skia `Picture` layers + React Native `View` / `Pressable` / `Text` overlays |

## Spacing Scale

Declared values (must be multiples of 4). Used for **React overlay chrome** (pause / win / lose / countdown / pause button), not for virtual playfield physics units.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline padding |
| sm | 8px | Compact element spacing, brick visual gap cue (render only) |
| md | 16px | Default overlay padding, button horizontal padding |
| lg | 24px | Overlay panel inner padding |
| xl | 32px | Stack gap between overlay title and actions |
| 2xl | 48px | Safe clearance above home-indicator for bottom CTAs |
| 3xl | 64px | Top chrome offset under status / notch for Pause affordance |

**Exceptions:**

| Exception | Value | Reason |
|-----------|-------|--------|
| Touch target minimum | 44×44 px | Pause, Resume, Retry, and any serve-hint hit area must meet iOS HIG / Android 48dp-adjacent floor (use 44 logical px minimum; prefer 48 where layout allows) |
| Countdown numeral | Display size, centered | Not spacing-token driven — see Typography |
| Logical playfield | 360×640 vu | Camera letterboxes into safe area; letterbox bars are Dominant-adjacent black (`#000000`) outside the navy field |

**Playfield letterbox (D-03 / research):** Fixed logical aspect 360∶640, scaled uniformly into the safe area; letterbox/pillarbox fills `#000000`. Opaque Skia canvas paints its own navy field (`#1a1a2e`) — never rely on transparency through Android TextureView.

## Typography

Overlay / chrome only (Skia gameplay entities have no text in Phase 3).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Overlay helper lines (“Tap Resume, then wait”) |
| Label | 14px | 400 | 1.4 | Secondary chrome (lives readout if shown, button sublabels) |
| Heading | 20px | 600 | 1.2 | Overlay titles: Pause, Win, Lose |
| Display | 48px | 600 | 1.0 | Countdown numerals `3` / `2` / `1` centered |

**Weights declared (exactly 2):** 400 (regular) + 600 (semibold).  
**Font family:** SpaceMono for all overlay text (matches Phase 1 spike). Do not introduce a second family in Phase 3.

**Source:** Spike uses SpaceMono 16 for HUD; Display size is Claude discretion (CONTEXT) for readable countdown at arm’s length.

## Color

60 / 30 / 10 split for the **first-playable screen composition** (playfield + overlays). Flat solid fills only — **no neon, glow, blur, particles, trails, or baked glow sprites** (D-01; Phase 7).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1a2e` | Playfield background fill (existing spike field color) |
| Secondary (30%) | `#000000` + scrim `#000000` @ 60% opacity | Letterbox bars; pause / win / lose / countdown overlay dimmers; overlay panel backing `#12121f` |
| Accent (10%) | `#FFFFFF` | Ball fill; paddle fill; primary CTA label text on dark overlays; countdown numeral |
| Destructive | `#E85D5D` | Lose overlay title only — not used for Retry button chrome |

**Row brick palette (flat solids; brightness encodes remaining HP within a row family):**

| Brick kind | Fill | Notes |
|------------|------|-------|
| Breakable HP 3 (full) | `#C44569` | Darkest in family |
| Breakable HP 2 | `#E07A5F` | Mid |
| Breakable HP 1 | `#F2CC8F` | Lightest — about to break |
| Unbreakable / structural | `#6B7280` | Steel gray; never animates to “damage” colors |

Accent reserved for:

1. Ball silhouette (must stay highest-contrast object on field)
2. Paddle silhouette
3. Primary CTA text / filled CTA background invert (`#FFFFFF` label on `#12121f`, or filled `#FFFFFF` button with `#1a1a2e` label)
4. Countdown Display numerals

**Never use accent for:** brick fills, letterbox, pause scrim, decorative borders, or the Phase 1 cliff-ramp cyan (`#00ffaa`) — that cyan remains **dev-overlay only** behind `PERF_OVERLAY` / cliff flags, not gameplay UI.

**Source:** CONTEXT D-01, D-02; `recordSprites.ts` `#1a1a2e`; FEATURES readability priority (paddle/ball over spectacle).

## Interaction Contract

### Playfield gestures (PHYS-01, PHYS-05, D-04…D-12)

| Mode | Gesture | Effect | Forbidden |
|------|---------|--------|-----------|
| Playing (ball in flight) | `Gesture.Pan` on **entire playfield** | Relative paddle intent: touch-down stores finger x + paddle x; deltas × snappy gain + minimal smoothing; clamp to arena; **never teleport** on re-press | Must not serve, pause, resume, or retry |
| Docked serve | `Gesture.Tap` (separate recognizer) **only while** `docked && !paused && !countdown` | Launch ball; angle from paddle position / classic paddle-relative map (same family as PHYS-04 clamps); **no aim line** (D-09); tap-only (D-10) | Pan must not launch; drag-release aim not allowed |
| Paused / countdown / win / lose | Playfield pan **ignored** for game actions | Overlay owns input | Pan must not Resume or Retry |
| OS interruption | `AppState` → auto-pause + **reset accumulator** | No catch-up spiral | Never auto-resume into live physics |

### Gesture / UI separation scheme (D-11, D-12) — locked

Concrete scheme (planner/executor must implement this or an equivalent that preserves the invariants):

1. **Two recognizers, mode-gated:** `Pan` always writes `paddleIntent` only when `phase === playing || phase === docked`. `Tap` (serve) is `enabled` **only** when `phase === docked`.
2. **Resume is never a playfield tap.** Resume is a React `Pressable` on the pause overlay (and only there). After OS background, show pause overlay again; player must hit **Resume**, then countdown.
3. **Retry / Pause** are React chrome controls (top-end Pause; overlay Retry), not Skia hit-tests and not pan endpoints.
4. **Simultaneous fingers:** If a pan is active, ignore serve taps until pan ends. Countdown and overlays set `pointerEvents` so the canvas underneath does not receive serve taps.
5. **Invariant test (manual + ideally unit on mode flags):** “Pan across playfield while docked moves paddle and does not launch”; “Pan while paused does not call Resume.”

### Pause / resume sequence (PLT-01, D-13…D-16)

```
Playing → [Pause button | AppState background] → Paused (overlay)
Paused → tap Resume → Countdown 3·2·1 (overlay, sim frozen, accumulator held/reset) → Playing
Win / Lose → Retry → reset run (lives 3, grid restored, docked serve)
```

- Mid-rally background ≥60s: return to Paused, no physics jump.
- Countdown: sim frozen; no paddle intent applied; display Display numerals centered.

### Lives / win / lose (RUN-02, D-17…D-20)

- Default **3** lives.
- Minimal lives readout: optional Label text `Lives · N` top-leading chrome (not a polished HUD — Phase 6). Acceptable Phase 3 minimum: lives implied by lose only, but prefer showing `Lives · N` for clarity.
- Win when last **breakable** brick destroyed; unbreakables never block win.
- Overlays: minimal — title + Retry only (D-19).

### Hardcoded grid (D-20)

- One in-code grid; must include multi-HP (≥2 HP values) and ≥1 unbreakable brick.
- Visual density: playable first-minute aim at a chosen brick (Roadmap SC-3). Exact layout Claude discretion.
