# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Why this contract exists, and what it is not

Phase 11 is already **Executed** — all six plans ran and the endless machinery is shipped.
This contract was generated after the fact because `/gsd-plan-phase 11 --gaps` hit the UI plan
gate, and the next step is gap-closure planning against
[`11-VERIFICATION.md`](./11-VERIFICATION.md) (`status: gaps_found`, 3/6 truths verified).

**This is therefore a contract over surfaces that already exist, not a redesign.** Its job is to
pin the visual and interaction contracts the shipped endless surfaces must honour, and in
particular to make the two recorded UI-contract defects *expressible*:

| Gap | Where | What this contract pins |
|-----|-------|-------------------------|
| **Gap 1** — `bestWave` inflates one per Retry, durably into AsyncStorage | `onRetry` (`PlayingHost.tsx:895-920`), `remountDevSession` (`1014-1038`) | [Interaction Contract § Run boundaries](#run-boundaries-endless) — an endless Retry is a NEW run at wave 1 |
| **Gap 2** — endless Results shows the **campaign** per-level PB as `Best` and fires `New Record` against an unrelated campaign score; `telemetry.endless` has no reader anywhere in `app/` or `src/` | `handleRunEnded` (`PlayingHost.tsx:597-645`), `ResultOverlay.tsx` | [Record Display Contract](#record-display-contract) — per-mode data sources, selected before `evaluatePersonalBest` |

**Explicit non-goals (Phase 14 scope, deliberately untouched here):**

- Any **production** entry point into endless. The `__DEV__` Pressable at
  `PlayingHost.tsx:1234-1242` is sanctioned Phase 11 scope (D-05) and is recorded as
  `deferred → Phase 14` in the verification report, **not** a gap.
- A **permanent** endless record surface (Title / stats screen) — `ENDLESS-MODE.md` § Limits
  item 4. Showing the *wrong* number on the endless Results overlay today is Phase 11's.
- Deciding **which record is "the" record** (best wave vs best score). This contract renders
  *both*, which is precisely how it avoids pre-empting that Phase 14 decision.
- Production placement of the wave indicator. It stays in the `__DEV__` dev row this phase.

**Continuity:** reuse `06-UI-SPEC.md` (shell/HUD/overlay chrome), which itself reuses
`03-UI-SPEC.md` (tokens, gesture/UI separation) and is extended by `D1-UI-SPEC.md` (juice).
Phase 11 introduces **zero new colors, zero new type sizes, zero new spacing tokens and zero
new packages.** Every value below is already in the codebase; this document states which ones
the endless surfaces are bound to.

| Error state (board) | `advanceToWave(n)` returns false: the run **ends** with the wave-build-failure body above. **Never** render `LevelErrorOverlay` for this — it has no controls and would trap the player with no exit |
| Destructive confirmation | **None.** `Retry` and `Menu` stay instant (RUN-03). The safeguard is not a dialog: any endless run-boundary reset **records the in-flight run first** (see Interaction Contract), so the wave reached is never silently lost |

**New Record rule (endless):** the badge fires when
`score > telemetry.endless.bestScore` **OR** `wave > telemetry.endless.bestWave`, both strictly
(D-11: equality keeps the previous record). Both count because a deeper run at a lower score is
unambiguously a new record, and firing on only one of them would silently elect a primary
record — the Phase 14 decision this contract defers.

**Line order is contract:** heading → body → `Wave ·` → `Score ·` → `Best ·` → `Best wave ·` →
badge → `Retry` → `Menu`. Wave precedes score because depth is what an endless run is about;
the two `Best` lines sit adjacent so the pair reads as one record block.

## Interaction Contract

### Record Display Contract

The Gap 2 fix, stated as data sources. **The mode branch must happen before
`evaluatePersonalBest` is called**, not after — the current defect is precisely that
`handleRunEnded` (`597-645`) computes the campaign comparison first and branches second.

| Field | Campaign source | Endless source |
|-------|-----------------|----------------|
| `Best · {n}` | `previousBestRef` ← `store.getBestForLevel(levelId)` | a **separate** endless watermark ref ← `getSnapshot().telemetry.endless.bestScore` |
| `Best wave · {n}` | not rendered | a **separate** endless watermark ref ← `getSnapshot().telemetry.endless.bestWave` |
| `New Record` | `score > campaignPB`, strict | `score > endlessBestScore` **or** `wave > endlessBestWave`, strict |
| Post-run write-back | `previousBestRef := best` when a record | the endless refs only; **`previousBestRef` must never be written by an endless run** |
| Stars / `Next` | rendered when earned | never rendered |

Consequences that are part of the contract:

- After an endless run, returning to a campaign level must show the **unchanged** campaign
  `Best`. Today the endless score poisons `previousBestRef` at `638-640`, which `onRetry` (`906`)
  and `remountDevSession` (`1024`) then re-display as the campaign best.
- The endless Results overlay is the **only** endless-record reader this phase ships. It exists
  because `telemetry.endless` currently has no reader anywhere in `app/` or `src/`. A permanent
  record surface stays Phase 14 (`ENDLESS-MODE.md` § Limits item 4).
- Displayed values are **post-merge**: if this run set the record, `Best`/`Best wave` equal this
  run's numbers — same convention as the campaign overlay.

### Run boundaries (endless)

Every path below must leave the run's identity consistent. The Gap 1 root cause is that these
resets were never made mode-aware: they reset lives/score/combo but not `waveRef`, `runSeedRef`,
`modeRef` or `waveAdvanceInFlightRef` — the only site that sets those is `startEndlessRun`
(`1048-1072`).

| Trigger | Contract |
|---------|----------|
| Endless Results → `Retry` | A **new run**: re-mint `runSeedRef`, `waveRef := 1`, mode stays `endless`, clear `waveAdvanceInFlightRef`, lives 3 / score 0 / combo 1. Route to `startEndlessRun()`; do **not** call the campaign `retry()` against the wave-N board |
| Pause → `Retry` during a live endless run | Same as above, **and record the in-flight run first** as `abandoned` at the wave reached, so the wave is never silently dropped |
| Pause → `Menu` during a live endless run | Record the in-flight run as `abandoned`, then Title. Title's `Best` line still reads the **campaign** best — unchanged by endless |
| `remountDevSession` during endless | Record as `abandoned`, then route to `startEndlessRun()`. Today it neither records nor resets wave/seed/mode |
| Wave clear (`WON` intercept) | **No chrome at all**: no overlay, no countdown, no `setActive(false)`, no toast, no flash. The board swaps in place, the ball re-docks, and `Tap to launch` reappears (D-03). HUD `Score`/`Lives`/`×combo` carry their values across the swap without resetting to 0 |
| `advanceToWave(n)` returns false | End the run: record `abandoned` at wave `n-1`, render the endless Results with the wave-build-failure body, and **clear `waveAdvanceInFlightRef`**. A latched guard swallows the next `WON` and is an SC-1 break |
| Lives → 0 | Endless Results overlay, lose variant |

If resuming at wave N is ever wanted instead of restarting, it must **not** feed `recordRunEnd`
unadjusted — carry a `runStartWaveRef` and record `wave - (runStartWave - 1)`, or refuse to raise
`bestWave` from a resumed run. This contract chooses restart-at-wave-1.

### HUD during an endless run

| Rule | Contract |
|------|----------|
| Wave indicator placement | The `W{n}` `Text` in the `__DEV__` dev row, beside the `Endless` button — **only** (D-05 / D-13, `ENDLESS-MODE.md` § Limits item 4) |
| `HudStrip` | Gains **no** wave field, no new row, no new color this phase. Production endless chrome is Phase 14 (N-UI-01 / N-UI-02) |
| Existing metrics | `Score · n`, `×combo`, `Lives · n`, `Stall! · tier` keep campaign semantics and gating verbatim during an endless run |
| Data path | Discrete React mirrors via `useAnimatedReaction` only — **never** a per-physics-frame `setState`. The wave counter is a cold-path value, updated once per transition |
| Obstruction | No centre-screen HUD, no opaque bar over brick rows, no wave-up banner |

### Shell rules (unchanged, restated)

- `PlayingHost` still unmounts when not playing; Menu returns to Title.
- AppState auto-pause, accumulator reset, `Resume` → 3·2·1 countdown — all unchanged, and a
  wave transition does **not** trigger a countdown.
- Playfield gestures inherited verbatim from `03-UI-SPEC.md`.
- Forbidden UI, unchanged: no ad banner/interstitial, no shop, no rewarded-continue, no sign-in,
  no IAP price label. An endless "continue for one more wave" offer is explicitly **not** in scope.
