<objective>
Turn the single tracer transition into the two multi-wave properties the phase is actually
promising: a run that keeps going (SC-1) and a run that replays (SC-4).

Purpose: SC-1 and SC-4 are the two roadmap criteria that a single transition cannot prove.
Research already ran both experiments — 30 waves with zero stuck waves, and two 12-wave runs
at seed 777 matching on `hashWorld` at all 12 boundaries and on final score — so this plan
is reproducing a measured result as a permanent guard, not discovering one.

Output: an expanded `tests/endless.wave-loop.test.ts` and a new
`tests/endless.determinism.test.ts`.

## Scope statement this plan must write down, not soften (SC-4)

**A device endless run is not replayable, and nothing here may imply that it is.** The
obstacle is not the RNG — it is the input stream. On device, intent is read per substep from
`paddleTarget.value`, and the number of substeps per frame depends on wall-clock frame timing
through the accumulator and the `MAX_SUBSTEPS` cap. Nothing records the per-tick intent
sequence, and adding such a recorder is a feature this phase does not have.

What IS provable, and what the suite asserts, is:

> given a run seed, the initial world seeds and a fixed input policy, an endless run replays
> to the same wave with the same score and the same `hashWorld` at every wave boundary.

Separately and unconditionally: the **board sequence** alone, independent of play, is
reproducible from the run seed — that is the part Phase 12's daily challenge inherits.

`tests/levelgen.determinism.test.ts:1-16` spends its entire header on exactly this kind of
"what the pins do and do not claim" statement. Copy that discipline; the header of the new
file is load-bearing, not decoration.
</objective>
