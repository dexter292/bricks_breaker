<objective>
Make SC-3 structural: an endless run must be physically incapable of writing campaign state,
and the endless record must live where a corrupt value cannot take campaign progress down
with it.

Purpose: research found a live defect — `recordRunEnd` writes `bestByLevel`, raises
`blob.bestScore` and calls `unlockAfterClearPure` for *every* mode, with no reference to
`args.mode` (`memoryStore.ts:93-122`, plus the third write inside `applyLevelBest` at
`:67-73`, mirrored at `asyncStorageStore.ts:364-405`). As written today, the first endless
win would silently write a campaign best and unlock a campaign level. This plan closes that
and adds `N-END-02`'s record in the one place whose parser already fails soft in isolation.

Output: `EndlessRecord` on `TelemetryBlob`, a sanitizer, a running-max merge, the mode gate
in both stores, and the test that proves the firewall.

## Decision made here, not deferred to the executor: `recordRunEnd` takes a discriminated union (D-11)

The runtime gate research asked for (`if (args.mode === 'campaign')`) is necessary but weak
— it is still possible to hand an endless run a `levelId: LevelId` and have a future edit
drop the gate. Research's own preference was stronger: *"Prefer making the argument a
discriminated union on `mode` so a campaign-only `levelId: LevelId` cannot be supplied for
endless at all."*

Do both. The union makes the campaign fields unreachable from the endless arm at compile
time; TypeScript's narrowing then *forces* the runtime gate to exist, because `args.levelId`
does not typecheck outside it. SC-3 becomes a property of the type, not of a caller
convention.

Blast radius measured before choosing: `grep -rn "recordRunEnd(" app/ src/ tests/` returns 16
lines, which is **13 invocations plus 3 declarations** — 1 invocation in
`app/_components/PlayingHost.tsx:548` and 12 in `tests/storage.progress-v4.test.ts`, against
declarations in `types.ts`, `memoryStore.ts` and `asyncStorageStore.ts`. Every one of the 13
invocations passes `mode: 'campaign'` and stays valid against the union unchanged, and no
source or test anywhere passes `mode: 'endless'` or `mode: 'daily'` today. The union gets a campaign arm and an endless
arm only — Phase 12 adds the daily arm when daily exists, and until then `daily` is
correctly excluded rather than silently treated as campaign.

Alternative rejected: keeping the flat argument type and relying on the runtime gate alone.
It leaves the defect one careless edit away from returning, and `levelId: LevelId` on an
endless run has no meaningful value to pass.

## Second decision: the endless telemetry key is a constant, not a `LevelId` (D-12)

`LevelId` is a five-member union of campaign ids and is the key type for `bestByLevel` and
`unlocked` (`src/core/levels/levelIds.ts:8-13`). Widening it to admit an endless value would
open every campaign-progress code path to endless values — the exact failure SC-3 forbids.
`mergeRunIntoTelemetry` already keys `byMode` on a plain `string`
(`telemetry.ts:97-112`), so the endless arm passes an exported
`ENDLESS_TELEMETRY_KEY` constant and `byMode.endless` accumulates under it for Phase 13.
</objective>
