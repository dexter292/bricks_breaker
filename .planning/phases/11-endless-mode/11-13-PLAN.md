<objective>
Close gap 3 of `11-VERIFICATION.md`: **an endless run that has ENDED does not stay ended.**

`applyChrome` is built around a single `runEndedRef` latch that every run-boundary branch consults
— campaign WON, LOST, and the mid-run wave-build failure all do. The endless WON branch
(`PlayingHost.tsx:929`) gates on `modeRef.current` and `waveAdvanceInFlightRef` only. The inner
`if (!waveAdvanceInFlightRef.current)` guards concurrency, not run lifetime. So after the run
boundary has fired, further WON mirrors keep regenerating boards and walking the wave: measured,
LOST at W2 then one WON mirror gives W3 with `advanceWave` called once and the compiled board
changed; four more pairs reach W6 with the lose overlay still up.

**Severity, stated honestly, because the code reviewer and the verifier disagree and the verifier
wins.** `11-REVIEW.md` CR-01 calls this CRITICAL. The verifier downgraded it after proving it
cannot inflate the record: from an ended run walked to W7, `Menu` records nothing (`runEndedRef`
latched) and `Retry` resets to W1 so the next loss records wave 1. Every path that clears
`runEndedRef` either routes through a wave-1 restart or exits to campaign. Reachability is also
bounded — `chromeSeq` bumps only when the mirror changes, and both ended states have already
called `setActive(false)`, so an in-app producer needs a straggler frame in the stop window. Plan
it as a real gap with honest severity: an incoherent ENDED state, a burned seed walk and a
self-contradicting overlay — not a false record.

The worst face of it is the copy. After a FAILED START, `failEndlessStart` leaves
`waveBuildFailedWave = 1` (body: `Wave 1 could not be built — tap Retry`, run-scoped lines
suppressed) and one WON mirror rewrites it to 2 — so the body becomes the mid-run
`Wave 2 could not be built — run saved` and `Wave · 0` un-suppresses for a run that never began.
That is exactly the class 11-09's IN-05 suppression exists to prevent.

Purpose: `applyChrome`'s whole design is one latch, every boundary. Phase 14 promotes this code
path. Output: the missing term, a uniform post-condition across all three ended-run states, three
behaviour cases the pre-fix code fails, and a count-based contract that catches the next branch
that forgets the latch.
</objective>
