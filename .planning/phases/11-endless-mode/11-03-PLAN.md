<objective>
Give the host a sanctioned way to ask for a wave advance, and keep run telemetry whole across
the `world.tick` reset that D-06 chose.

Purpose: JS may never mutate `world.value` — Reanimated hands JS a crossing-time clone and
in-place mutation does not propagate (the repo learned this on device: a run that broke
bricks persisted `bricksBroken: 0`, `useGameLoop.ts:174-181`). The request/apply counter pair
is the only route, and there are already three of them. This plan adds the fourth and the
tick bank that D-06 made necessary.

Output: `waveRequest`/`waveApplied` shared values, an apply block in `onFrame`, `advanceWave`
on `GameLoopHandle`, and a cumulative tick bank.

## Decision made here, not deferred to the executor: the tick bank lives on the UI runtime (D-06 consequence 2)

Plan 11-01 chose to reset `world.tick` each wave. `publishRunStatsMirror(runStatsOut.value, stats, w.tick)`
at `useGameLoop.ts:454` publishes `w.tick` straight through as `ticksPlayed`, so without a
bank a 25-wave run would report only the final wave's simulated time.

**The bank is a `useSharedValue` in `useGameLoop`, incremented by `w.tick` inside the
wave-advance request block, and added to `w.tick` at the publish call.** The bank is zeroed in
the `resetRequest` block alongside `resetRunStats`, because a retry IS a new run.

The alternative the CONTEXT named — banking in the app tier the way `runWallClockMsRef` banks
wall-clock segments (`PlayingHost.tsx:245-264`) — is the right *shape* and the wrong *tier*.
Wall-clock segments open and close on React state transitions the JS tier already owns, so a
ref there is exact. `world.tick` exists only on the UI runtime and is reset inside a worklet;
banking it in the app tier would require the final pre-reset `runStatsSeq` `runOnJS` to be
delivered before the `chromeSeq` `runOnJS` that triggers the advance — an ordering between two
independent `useAnimatedReaction`s that nothing in Reanimated guarantees. Banking where the
reset happens is race-free by construction. The segment-accumulator pattern is preserved; only
its address changes.
</objective>
