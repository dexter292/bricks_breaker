## Why this plan depends on 12-02, and not only on 12-01

Task 3 of this plan runs `tests/storage.daily-firewall.test.ts` as a gate. That file is **plan
12-02's artifact**, and the dependency is declared here rather than left implicit for a reason
that has a measured failure mode: when the two plans share a wave, wave-parallel execution can
start this one before that file exists, and `vitest` then exits **1** with
`No test files found, exiting with code 1` — the same behaviour this phase already measured for
`npx vitest run tests/daily`. The gate would red for a reason unrelated to this plan's work.

The wave guard cannot see that coupling on its own: it compares `files_modified`, and this plan
does not modify the firewall spec — it only *targets* it. A verify target is a dependency just as
much as a shared file is, and it is declared as one.

The edge is also semantically honest rather than a scheduling trick. The D-16 scalars this plan
adds land on the very record 12-02's firewall suite asserts against; 12-02 was written to assert
cardinality and absence rather than whole-record equality **precisely so** this addition does not
red it. That contract is only checkable once 12-02 has shipped, which is exactly what the edge
now guarantees.

Consequence for the phase: waves become 1 → `12-01`, 2 → `12-02`, 3 → `12-03`, 4 → `12-04` ∥
`12-05`, 5 → `12-06`. Waves 1, 2, 3 and 5 are single-plan, so every tree-wide gate in them
observes a quiescent tree.

  <context>
`12-CONTEXT.md` rates D-16 **one-way**: "once players have accumulated these numbers there is no
way to reconstruct them from a trimmed history, so a later schema change must migrate them rather
than recompute them." That is the whole reason this checkpoint exists — every other decision in
this phase is additive to a blob and reversible by editing a type.

There is also a sub-question the codebase gives no answer to. `mergeEndlessRecord`'s reconciler
(`telemetry.ts:205-211`) is a pure per-field maximum, which is right for `longestStreak` and
**wrong** for `totalDaysPlayed`: max-merging two devices' counts loses days, and summing them
double-counts every date both copies hold. The only in-repo precedent that does both in one
function is `mergeAggregates` (`telemetry.ts:161-183`), which sums cumulative fields and maxes
the "ever" fields, with the sum-vs-max contract stated at `telemetry.ts:5-8`. The daily record is
the first structure in the blob that needs both behaviours in one object.

Two discretionary numbers were fixed by plan 12-01 and are restated here so this checkpoint is
the single place all three are confirmed together: `DAILY_DIFFICULTY = 10` (the generator's
published table puts `d = 10` between `level-01`'s 32 bricks and `level-03`'s 94-brick showpiece,
at a ~2-minute median clear, and exactly where endless arrives at wave 11) and
`DAILY_HISTORY_BOUND = 400` (~45 bytes per entry × 400 ≈ 18 KB against the ~2 MB Android
CursorWindow practical ceiling the shipped ring-buffer comment already names; 400 over 365 because
the window size is directly the longest ended streak the UI can ever report as ended).
  </context>

**`src/services/daily/dateKey.ts`** gains two exports:

`previousDateKey(key: string): string` — pure string to string, the local calendar date exactly
one day before `key`. Build it from the parsed year, month and day with the local-field `Date`
constructor and a day of `day - 1`, anchored at **midday, not midnight**, and run the result back
through `localDateKey`. The midday anchor is the point: the field being stepped is the day, and a
midnight anchor can land on a local hour that does not exist on either side of a DST step. State
that reason in the doc comment.

`isValidDateKey(raw: unknown): raw is string` — shape check against a four-two-two digit pattern,
then integer range checks on month and day with a days-in-month table and the standard leap rule
(divisible by 4, except centuries, except every 400th). Integer arithmetic and comparisons only —
no exponentiation, no date parsing round trip, matching the no-approximated-arithmetic rule
`src/levelgen/schedule.ts:50-55` sets and `src/services/endless/ramp.ts` restates. A round trip
through date parsing would accept strings the format does not, and would re-introduce exactly the
ambient-input dependency this module exists to avoid.
