## Instrument decision this plan makes explicitly

`14-PATTERNS.md` § No Analog Found records that this screen needs three things with no precedent in
this repo, and that the plan must decide them rather than infer them:

1. **A control fixed outside a scrolling subtree.** The only `ScrollView` in `src/` or `app/` is
   `LevelErrorOverlay.tsx`, which renders ZERO `Pressable` nodes by design. The fixed-header
   STRUCTURE transfers; the reachability claim does not, which is why the device backstop exists.
2. **A `flex: 1` full-screen `ScrollView`.** `LevelErrorOverlay`'s scroll is a panel idiom with a
   fixed `maxHeight` inside a percentage-height panel. **Do not copy that `maxHeight`.** This screen
   needs `flex: 1` on the `ScrollView` under a fixed header.
3. **A production `testID`.** `git grep testID src app` returns ZERO — every occurrence in the repo
   is inside a `vi.mock` factory. **Decision: add one**, `testID="achievements-scroll"` on the
   `ScrollView`, and say so in the component's doc comment. Reason: `14-VALIDATION.md` B4 names the
   render-tree assertion as "the load-bearing one" for the sanctioned scroll, a source-contract
   cannot observe a render tree, and react-native-web's internal class names are brittle to assert
   on. The `testID` is inert in production (it maps to a `data-testid` attribute on web and to an
   accessibility identifier on native) and is the minimum that makes the load-bearing half
   observable. A second, independent source-contract instrument is added alongside it, because this
   is the one criterion in the phase with no analog.
